# Design

## Context

См. мотивацию в `proposal.md`. Первый раунд реализации уже добавил descriptor/parser/build discovery и профили, перевёл кафе и обобщил E2E. Остальные 18 ресурсов пока читает `src/legacy_datasets.rs`. Пользователь уточнил объём: все встроенные наборы должны иметь одну форму; этот документ заменяет прежнее решение о сохранении двух форматов.

Typing, RU→EN и RU→ES продолжают использовать существующие таблицы `word_sets`, `translation_sets`, `vocabulary_sets`/`vocabulary_entries`. Общий descriptor-seed уже добавляет отсутствующие id; после удаления прежних seed-процедур это правило применяется ко всем встроенным наборам, включая Typing при непустой таблице.

## Goals / Non-Goals

**Goals:** одна форма всех 19 встроенных наборов, один документированный путь добавления файла, автоматическое встраивание и проверка, профиль вместо исключения по id, повторное использование текущих таблиц и упражнений.

**Non-Goals:** редактура учебного материала, универсальный движок курсов, runtime-импорт, новые языки/режимы/голоса, UI описаний и автоматическое обновление уже сохранённых словарей. Исходный enum профилей закрыт и отражает только действующее поведение.

## Decisions

### 1. JSON и пять готовых профилей

Использовать уже имеющийся JSON/Serde, не добавлять YAML/TOML или ссылки на отдельный файл записей. Минимальный новый набор выглядит так:

```json
{
  "schema_version": 1,
  "id": "cafe_practice",
  "description": "Кафе и знакомство: первые испанские фразы",
  "profile": "spanish-phrases",
  "level": "beginner",
  "entries": [
    {"id": "cafe_practice:hola", "ru": "привет", "target": "Hola"}
  ]
}
```

Оболочка одинакова для всех наборов. Для Typing entries — массив строк; для трёх переводных профилей — `id/ru/target`: различаются только данные, обусловленные смыслом упражнения. Профили и их правила заданы в spec. Отдельных произвольных `languages`, `modes`, `case_sensitive` и TTS-настроек нет: metadata `profile` однозначно задаёт согласованную политику, включая регистр. Так новый файл не может обещать неподдерживаемую комбинацию. Отсутствующий level в адаптере получает нейтральное `custom`. Description хранится вместе с материалом для автора; TUI продолжает показывать id, без нового экрана.

Общий небольшой модуль разбирает и валидирует формат; он используется сборкой и тестами без отдельных реализаций правил. Структурные ошибки, неизвестные поля/версия/профиль, пустые значения, повторные id и нарушения профиля возвращают адресную ошибку. Проверка дублей target сравнивает точные NFC-строки, не меняя регистр и диакритику. Она не заменяет проверку смысла русских переводов. Ограничение испанских target буквами и пробелами берётся из текущих проверок A1–C2/кафе: поддержку произвольной пунктуации v1 не добавляет.

### 2. Обнаружение и встраивание при сборке

Добавить `build.rs`: просмотреть непосредственно `resources/datasets/*.json`, отсортировать пути, проверить общим валидатором, сгенерировать список встроенных данных в `OUT_DIR`. Файлы встраиваются в бинарник; runtime не обращается к исходному каталогу. Указать Cargo зависимость как от каталога, так и файлов, чтобы обычная повторная сборка замечала добавление/удаление. Использовать текущие версии serde/serde_json/Unicode-зависимостей как build dependencies при необходимости; отдельный генератор, crate и кодогенерация в репозитории не нужны. Проверить включение каталога в Cargo package.

Все 19 наборов находятся в `resources/datasets/`. Удалить `src/legacy_datasets.rs`, его ссылки в build/main/configuration и старые отдельные seed-процедуры; discovery становится единственным источником поставки и диагностики коллизий. Исходные пять TXT и тринадцать старых JSON после проверенного преобразования удаляются. Не сохранять резервный формат, ручной список встроенных id или валидатор с исключениями для перенесённых наборов.

Readonly-аудит исходных ресурсов подтвердил совместимость с текущим общим валидатором: нет NFD, пустых/неподходящих строк, внешних пробелов или повторов target внутри переводного набора; все RU-поля содержат русские буквы. Повторяющиеся RU-значения (например, «я» и «все» в A1) и слова между наборами допустимы и сохраняются. Typing содержит соответственно 1000, 10000, 4977, 10000, 50000 записей; семь RU→EN — 996/1000/1000/1000/944/896/61, ES A1–C2 — 5675, кафе — 31. Данные не нужно исправлять для миграции. Преобразование сохраняет порядок; RU→EN получает `name:0`, `name:1`, …, как нынешний `get_shuffled_vocabulary`, испанские id копируются. Сохранность проверяется одноразовым сравнением с исходниками из HEAD, без постоянной второй копии словаря.

### 3. Адаптеры к текущей БД и выбору

На старте декларативные наборы транзакционно добавляются только при отсутствии id: typing-профили в `word_sets`, RU→EN в `translation_sets`, испанские — в vocabulary-таблицы. Адаптер преобразует `target` в текущие поля `en`/`es`; внутреннюю модель всех режимов переименовывать не требуется. Настройки и схема БД сохраняются. При совпадении с существующей строкой её данные не перезаписываются; несовместимые язык/тип дают понятную ошибку выбранного набора, а не новую интерпретацию старых данных.

Получать профиль каждого встроенного набора по metadata независимо от его имени. Для локальных наборов без descriptor сохранить fallback по фактической таблице/языку SQLite: word_sets ru/en → соответствующий Typing, translation_sets ru/en → Translation, vocabulary_sets ru/es → прежняя строгая ES-политика. Это совместимость хранения пользовательских данных, а не второй формат поставки; существующие строки не валидируются заново как исходные файлы и не переписываются. Готовые списки режимов и case policy уже поступают из configuration. Сохранить порядок выбора, дефолты и restart-политику; миграция БД не нужна.

### 4. Что меняется относительно предыдущего обновления

| Область | Действие |
| --- | --- |
| Все ресурсы | Перевести оставшиеся 18 наборов в папку descriptors; кафе уже в нужном формате. Сохранить тексты, количество, порядок и идентичность записей |
| Ручная регистрация / отдельные seed-процедуры | Удалить, оставить одну поставку descriptors; прежняя ветка кафе в App уже удалена |
| Поддержка нечувствительного регистра и безопасная подсказка Dictation | Сохранить, получать настройку из профиля |
| 506 строк cafe-specific тестов | Перенести полезные сценарии в общие проверки каталога/профилей; удалить дублирующие циклы выбора и жёсткий список 31 пары после проверки сохранности миграции |
| README/каталог/испанский валидатор | Указать единую папку/формат. Валидатор A1–C2 читает descriptor entries/target и сохраняет содержательные проверки шести уровней, не участвуя в регистрации ресурсов |
| SDK evidence, прежние результаты и OpenSpec-артефакты | Сохранить как историю; не выполнять полный revert и не закрывать прежние незавершённые проверки |

### 5. Общие проверки вместо теста на каждый словарь

Один набор unit/интеграционных проверок перебирает автоматически обнаруженные descriptors: формат, коллизии, записи после seed и соответствие профиля. Общий Unix E2E через `wpm` подтверждает доступность каждого descriptor в положенных списках; сценарии запуска, сохранения, ввода, ошибок и выхода параметризуются пятью профилями на малых детерминированных фикстурах, а не повторяются на каждом словаре. Сохранить проверки фраз, case, диакритики, RU-клавиш, скрытого ответа, TTS, F2/restart и неполного ответа из кафе-тестов. Размер каталога и порядок выбора не зашивать в число нажатий.

Отдельная общая acceptance-проверка работает во временной копии проекта: собрать, добавить только новый descriptor с id без языкового префикса, снова собрать в том же target directory и запустить бинарник через PTY из пустого каталога. Проверить появление и запуск в обоих испанских режимах, затем изменение/удаление файла при очередной сборке на свежем `WPM_DATA_DIR`. Несколько ошибочных fixtures подтверждают адресные ошибки сборки и конфликт с существующим descriptor. Проверка не меняет рабочее дерево и не требует runtime test-only API. Добавление файла в эту проверку выполняется программно, ручные списки примеров в тестах не обновляются при каждом новом наборе.

## Risks / Trade-offs

- [Механическое преобразование затрагивает большие файлы] → сравнить упорядоченные данные каждого из 19 наборов с исходниками; не смешивать миграцию с исправлением переводов или количества записей.
- [Новая сборка не меняет уже сохранённые записи] → явно описать это в инструкции; проверять обновление файлов на свежем `WPM_DATA_DIR`, не стирать пользовательскую БД.
- [Общие проверки могут потерять полезные cafe-сценарии] → составить короткое соответствие старых сценариев новым профилям и проверить сохранность 31 пары при миграции; не создавать вторую постоянную копию словаря в тестах.

## Migration Plan

В продолжающемся apply перевести все ресурсы, проверить равенство и удалить пути старой поставки; итоговая сборка содержит только descriptors. При обновлении существующие строки остаются на месте, metadata сохраняет прежние политики. Откат не требует удаления или преобразования БД. Реальное звучание, аудиодвижок и тексты не меняются, поэтому новый ручной аудиогейт не добавляется; открытые проверки прошлого изменения остаются открытыми. Прежние 8 выполненных задач и evidence отмечены как история первого раунда; завершение нового объёма требует задач раздела 4.
