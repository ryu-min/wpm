# Proposal

## Why

Добавление набора кафе потребовало ручной регистрации в Rust, ветки поведения по его имени и отдельного большого файла E2E. Все встроенные наборы должны иметь одну декларативную форму и один путь загрузки, чтобы новые данные не требовали специальных изменений кода.

## What Changes

- Установить единый формат для всех встроенных наборов: один `resources/datasets/<id>.json`, содержащий идентификатор, описание, профиль и записи. Перевести в него все 19 наборов: пять Typing, семь RU→EN, шесть ES A1–C2 и кафе. Добавление данных не требует изменений исходников, Cargo manifest, реестра наборов или персонального E2E-файла.
- Один раз реализовать обнаружение, валидацию и встраивание этих файлов при сборке. Установленный бинарник остаётся самостоятельным и не читает словари из текущего каталога.
- Поддержать только существующие профили: Typing RU/EN, Translation RU→EN и общие RU→ES наборы для Translation/Dictation со строгим либо нечувствительным к регистру диктантом. Профиль определяет существующие языковые правила и допустимые режимы; имя набора не определяет поведение.
- Сохранить id наборов, тексты, порядок и существующие повторы без редакторских изменений. У испанских записей сохранить id; для RU→EN зафиксировать нынешние синтетические id по индексу. Кафе сохраняет все 31 пару и прежнее поведение.
- Удалить `src/legacy_datasets.rs`, ручные реестры ресурсов, отдельные старые seed-процедуры и исходные TXT/JSON прежнего формата. Все встроенные данные проходят один loader/validator/seed; совместимость существующей SQLite остаётся задачей адаптера хранения.
- Свести общие сценарии из `e2e_spanish_cafe.rs` в повторно используемые проверки каталога и профилей. Новые файлы автоматически охватываются структурными проверками и проверкой доступности через бинарник; корректность переводов проверяется редактурой данных.
- Описать короткий процесс добавления набора и проверить его временным новым файлом: повторная сборка обнаруживает его без других правок, бинарник показывает его в нужных режимах.
- Перевести проверку испанских уровней и документацию каталога на ту же папку descriptors; сохранить содержательные ограничения A1–C2, не создавая для них второго формата или загрузчика.

## Capabilities

### New Capabilities

- `declarative-exercise-datasets`: контракт одного файла набора, существующие профили, автоматическая поставка, диагностика, совместимость и общая приёмка новых данных.

### Modified Capabilities

Нет изменения опубликованных требований к установке и раскладкам. Поведение действующих испанских режимов и набора кафе сохраняется; их активные изменения не архивируются и не объявляются завершёнными.

## Impact

Это однократное инфраструктурное изменение: общий модуль описания/валидации, build-time embedding, небольшие адаптеры текущего SQLite-каталога, передача списка допустимых наборов и профиля диктанта, общие тесты и документация. Без новой схемы БД, новых языков, режимов, пользовательского импорта или редактора.

Миграция всех встроенных ресурсов — механическая смена представления с проверкой равенства данных; исключений для старого формата не остаётся. Схемы локальной SQLite, сохранённые выборы и пользовательские правки не переписываются. Из `4b51edd` обобщаются регистрация, выбор политики и дублирующие тесты; сохраняются данные кафе, существующее сравнение фраз, полезные проверки и результаты SDK-диагностики. Полный revert коммита не выполняется.

После реализации обычное добавление набора меняет один файл данных и обязательные артефакты OpenSpec по правилам проекта. Новая семантика упражнений по-прежнему требует отдельного изменения кода и спецификации. Уточнение единой формы входит в ранее порученную реализацию этого изменения; прежняя приёмка варианта с двумя форматами не завершает новый объём.
