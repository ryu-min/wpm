# Design

## Context

На текущем Mac `xcode-select -p` указывает на CommandLineTools, а `xcrun --show-sdk-path` возвращает `MacOSX27.0.sdk`. В том же каталоге имеется `MacOSX15.4.sdk`. Основной агент воспроизвёл ошибку линковки без переопределения SDK и успешный запуск с SDK 15.4. `.cargo` в checkout отсутствует; `.gitignore` пока исключает только `target` и `.idea`. Переключение на установленный Xcode требует принятия лицензии и не входит в поручение.

## Goals / Non-Goals

**Goals:** запуск обычного `cargo run` из этого checkout без предварительного `export SDKROOT`, при сохранении явного пользовательского переопределения и переносимости отслеживаемых файлов.

**Non-Goals:** ремонт или переустановка системного toolchain, принятие лицензии Xcode, глобальный выбор SDK, автоматический поиск SDK на всех платформах, новый wrapper вместо Cargo.

## Decisions

### Локальная конфигурация Cargo

Создать в этом checkout неотслеживаемый `.cargo/config.toml`:

```toml
[env]
SDKROOT = { value = "/Library/Developer/CommandLineTools/SDKs/MacOSX15.4.sdk", force = false }
```

Абсолютный путь здесь — проверенное локальное значение этого Mac, а не настройка, распространяемая с проектом. Cargo читает конфигурацию из текущего каталога и родителей; `[env]` передаёт переменную запускаемым процессам, а отсутствие принудительного переопределения сохраняет значение из окружения. Эти свойства описаны в [официальном руководстве Cargo](https://doc.rust-lang.org/cargo/reference/config.html#env).

Выбран этот вариант, поскольку он меняет стандартный `cargo run` без shell-настройки и дополнительной команды. Конфигурация в домашнем каталоге Cargo затронула бы другие проекты; общий tracked SDKROOT перенёс бы путь на чужие Mac/Linux/Windows; wrapper добавил бы новую точку запуска и поддержку логики обнаружения. Они не нужны для подтверждённой локальной неисправности.

### Отслеживаемые изменения

В `.gitignore` добавить только `/.cargo/config.toml`, не скрывая весь `.cargo`. В README добавить компактный раздел для разработчика о локальном выборе SDK при несовместимом toolchain. Показать TOML с заменяемым путём к установленному совместимому SDK, объяснить приоритет переменной окружения и удаление локальной настройки после обновления toolchain. Не рекомендовать SDK 15.4 как обязательный для всех пользователей.

Существующие изменения README и других файлов сохраняются. Если к моменту реализации локальный конфиг появился, дополнить его без перезаписи посторонних ключей; при конфликтующем `SDKROOT` сначала проверить его актуальность. Учесть, что старое имя `.cargo/config` имеет приоритет над `.cargo/config.toml`, если такой файл неожиданно появился.

### Приёмка

Из окружения проверочного процесса удалить `SDKROOT`; не задавать его префиксом команды. Запустить `cargo run` из корня checkout в псевдотерминале с изолированным `WPM_DATA_DIR`, увидеть главное меню и выйти штатно. Для доказательства исправленной сборки, а не использования старого бинарника, отдельно выполнить сборку с пустым временным `CARGO_TARGET_DIR`; не применять `cargo clean` к текущим артефактам коллег.

В том же окружении без внешнего `SDKROOT` выполнить существующий `cargo test --locked --all-features --all-targets`. Проверить `git check-ignore -v .cargo/config.toml` и отсутствие локального файла в `git ls-files`. Изменение не добавляет пользовательского поведения, поэтому новые тесты приложения не требуются; воспроизведение команды сборки и запуска является непосредственной проверкой инструментария.

## Risks / Trade-offs

- Локальный SDK может исчезнуть после обновления инструментов → инструкция объясняет замену пути или удаление `.cargo/config.toml`.
- Пользователь явно задаёт несовместимый `SDKROOT` → это значение сохраняет приоритет; локальный default не должен его молча исправлять.
- Настройка не переносится в новый checkout → это намеренно; другой checkout выбирает свой SDK штатно либо настраивается по инструкции.
- Запуск Cargo из другого рабочего каталога с одним `--manifest-path` может не прочитать этот конфиг → приёмка и инструкция относятся к запуску из корня checkout.

## Migration Plan

Добавить ignore и документацию, затем локальный конфиг, выполнить проверки. Откат локального обхода — удалить только добавленную запись SDKROOT или созданный конфиг целиком, если иных настроек нет. Системные файлы и пользовательские данные не меняются.
