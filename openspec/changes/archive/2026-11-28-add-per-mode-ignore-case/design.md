# Design

## Context

Мотивация и область изменения описаны в `proposal.md`, проверяемое поведение — в `specs/typing-case-policy/spec.md`. Дизайн нужен, поскольку изменение затрагивает настройки, координацию запуска, предметную модель и отображение.

`Settings` в `src/domain/settings.rs` хранится целиком в JSON через `src/storage/settings.rs`. `SettingsWidget` редактирует клон настроек, Enter сохраняет его, Escape отбрасывает. В нём есть секции `Quick Start`, `Translation`, `Typing`; `Typing` содержит настройку раскладки.

`App::start` создаёт `TypingSession` для Typing и Translation. Все способы запуска и Restart сходятся в этой точке. Translation получает языковую политику по графемам: русский и английский используют конвертацию раскладки, испанский — также допустимые замены диакритики, разделители — точное сравнение.

`TypingSession::correct_count` и `TypingWidget` сейчас отдельно вызывают общий строгий `language::equivalent`. WPM и Accuracy уже используют один числитель правильных символов.

## Goals / Non-Goals

**Цели:**

- Поместить политику регистра в принадлежащую приложению сессию, чтобы UI и статистика не расходились.
- Добавить совместимые поля настроек без миграции SQLite и без изменения материала упражнения.
- Сочетать регистр с существующими языковыми правилами, не меняя строгий путь проверки.

**Вне области:**

- Изменения формата упражнений и профилей.
- Настройки регистра по набору, отдельный флаг Quick Start, новые зависимости и переработка формата descriptors.
- Нормализация хранимых данных или введённого текста, общее удаление диакритики, фонетическая транслитерация и сопоставление нескольких графем одной букве. Поддерживаемый контракт регистра относится к русскому, английскому и испанскому вводу; полноценный Unicode case folding с изменением длины не добавляется.

## Decisions

### Два поля настроек с безопасным отсутствующим значением

Добавить `typing_ignore_case: bool` и `translation_ignore_case: bool` с `#[serde(default)]` и `false` в `Default`. Это повторяет существующий подход `typing_layout_conversion`; общий флаг не обеспечивает независимость режимов, а карта по режимам усложняет столь небольшой фиксированный набор.

В соответствующих секциях Settings добавить по строке `Ignore case:` и значению `< On >` / `< Off >`; управление — Left выключает, Right включает, как у конвертации раскладки. Обновить число строк и размещение элементов, сохранив доступность подсказки управления. Ни модель выбора режима, ни Quick Start не получают новых локальных переключателей.

### Политика принадлежит TypingSession

При создании сессии в `App::start` передавать поле соответствующего режима. Сессия хранит флаг независимо от `Language` по графемам; пользовательский регистр применяется ко всему тексту, а языковая политика сохраняет нынешние границы. Restart автоматически получает сохранённое значение из той же точки запуска.

Предоставить предметный метод оценки позиции/пары графем с учётом языка и флага, используемый одновременно `correct_count` и `TypingWidget`. Не дублировать новый алгоритм в UI. Результат и late combining marks продолжат вычисляться через сессию; исходные `target_text`, `input_text` и массив языков не преобразовывать.

Альтернатива приводить всё упражнение к нижнему регистру при запуске отвергнута: она меняет показ образца, усложняет графемные позиции и способна нарушить клавиши с Shift. Расширять `Language` комбинациями регистра тоже не нужно: язык и пользовательская настройка независимы.

### Новый путь сравнения поверх неизменного строгого алгоритма

Сохранить сигнатуру и семантику `language::equivalent`. При `Off` сессионный метод вызывает существующее сравнение без дополнительных преобразований. При `On` сначала проверяет исходные графемы тем же алгоритмом; при несовпадении пробует регистровые варианты букв обеих графем, каждый раз применяя исходную языковую политику. Небуквенные символы не получают Shift-вариантов. Варианты должны оставаться одной NFC-графемой; изменение числа позиций не допускается. Для поддерживаемых RU/EN/ES достаточно исходного, нижнего и верхнего регистра; при необходимости этот отдельный helper размещается в `domain/language.rs`.

Это сохраняет допустимое `:` → `Ж`, добавляет `;` → `Ж`, `:` → `ж` и `Ж` → `;`, но не разрешает `:` → `;`. Простой вызов строгого алгоритма только на lowercase не подходит: `:` остаётся двоеточием, а цель `Ж` превращается в `ж`, и прежнее правильное соответствие теряется. Только преобразование ввода тоже недостаточно для `;` → `Ж`.

Испанское упрощение применяется после выбора варианта регистра только там, где уже задан `Language::Spanish`: `anu` и `фтг` принимаются для `ÁÑÜ`, а `ñ` для английской `N` не становится допустимым. Конвертация выключенного Typing по-прежнему недоступна независимо от регистра.

### Согласование с существующими OpenSpec-изменениями

В основной `keyboard-layout-conversion` нет отдельного требования строгого регистра; её правила раскладки сохраняются. В `openspec/specs/` пока отсутствуют испанские и профильные контракты, поэтому здесь создаётся новая capability `typing-case-policy`, без фиктивных `MODIFIED` для отсутствующих основных требований. Эта capability нормативно задаёт узкое исключение при `On`; базовое поведение при `Off` сохраняет ранее принятые сценарии.

| Источник ещё не синхронизированного контракта | Взаимодействие с новым поведением |
| --- | --- |
| `add-spanish-translation-and-dictation/specs/keyboard-layout-conversion`: «Общие правила испанского ввода» | Строгий регистр остаётся правилом по умолчанию; в Translation `On` разрешает различия регистра, не меняя общие испанские замены. |
| `add-spanish-cafe-beginner-set/specs/spanish-cafe-beginner-set`: «Печать канонических фраз в Translation» | Канонический показ и полный ввод пары сохраняются; строгий регистр относится к `Off`. |
| `data-driven-exercise-datasets/specs/declarative-exercise-datasets`: «Профиль выбирает только существующее поведение» | Пользовательский `On` меняет только регистр Typing/Translation. Пример Translation со строгим регистром остаётся верен при `Off`. |

Реализация уже содержит эти возможности, поэтому незавершённые исторические приёмочные задачи не являются зависимостью новой реализации. В этом изменении чужие planning artifacts не переписываются, синхронизация и архивирование не выполняются. При последующем явно запрошенном согласовании основных спецификаций следует перенести базовые контракты перечисленных changes и эту новую capability, сохранив ссылки на её исключение в формулировках строгого регистра и профильной политики. Если старые контракты будут синхронизированы раньше текущего apply, план требуется актуализировать полноценными `MODIFIED` для уже существующих требований до реализации; нельзя оставлять безусловные противоречащие формулировки. Это зависимость порядка публикации спецификаций, а не повод менять чужие задачи сейчас.

### Приёмка через терминал с предметными проверками крайних случаев

Добавить группу `tests/e2e/case_policy.rs` и подключить её в `tests/e2e/main.rs`; использовать `TestDataDir`, изолированный `WPM_DATA_DIR`, короткие фиксированные наборы и существующий запуск `wpm` через `script`. Настройки включать через терминальный UI; JSON подготавливать непосредственно только для проверки совместимости отсутствующих полей. Проверять обе противоположные комбинации флагов, все пути запуска и Restart, RU/EN/ES, обычный точный Typing с выключенной конвертацией, конвертацию с Shift-пунктуацией, неверные буквы и испанские границы языка.

Текущий `screen_from_output` отбрасывает ANSI-стили. Добавить минимальную возможность извлечь стиль проверяемой ячейки из того же терминального вывода, не ослабляя существующие текстовые проверки и не проверяя последовательности ANSI как нестабильную строку. Проверить правильный зелёный и ошибочный красный зачёркнутый символ до завершения упражнения в обоих режимах, сохранение канонического текста и исправление Backspace. Для полного правильного ввода проверить 100% и ненулевой WPM; при Off и всех неверных буквах — 0% и нулевой WPM. Точное численное сравнение WPM двух живых запусков неустойчиво из-за времени, поэтому формулу с одинаковым зафиксированным временем и одинаковым числителем дополнительно проверить на уровне `TypingSession`.

Сохранить регрессии существующих `layout_policy`, `spanish_translation` и `dataset_profiles`. Проверки поздней составной графемы, Unicode и всей таблицы RU/ENG выполнить предметными тестами и представительными E2E-сценариями, не заменяя ими наблюдаемую терминальную приёмку.

## Risks / Trade-offs

- Расхождение подсветки и статистики → один сессионный метод допустимости и E2E со стилями, дополненные проверкой формулы WPM.
- Повторные Unicode-преобразования при отрисовке → варианты строятся только после неудачного прямого сравнения; новый алгоритм не меняет графемную индексацию. Отдельная оптимизация без измеренной необходимости не требуется.
- Сдвиг строк Settings ломает навигацию или обрезает элементы → E2E проверяет доступность всех новых строк, сохранение и отмену при штатной геометрии терминала; существующие сценарии остальных секций сохраняются.
- Старые ещё активные specs безусловно описывают строгий регистр → нормативное исключение в новой capability, явная таблица выше и согласование при будущей публикации спецификаций.

## Migration Plan

Новая версия читает старый JSON без сброса настроек; оба отсутствующих поля становятся `false`. При обычном сохранении записываются новые поля. Миграция SQLite, правка встроенных наборов и массовая перезапись пользовательских данных не нужны. При откате старый serde-десериализатор игнорирует неизвестные поля; прежняя строгая проверка Typing/Translation возвращается, значения новых полей могут исчезнуть при сохранении старой версией. Пользователь также может вернуть прежнее поведение без отката, установив оба переключателя в `Off`.
