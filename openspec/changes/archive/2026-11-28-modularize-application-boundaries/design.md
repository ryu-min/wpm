# Design

## Context

Актуализировано 16 ноября 2026 в рамках [remove-dictation](../remove-dictation/proposal.md). Выполненные этапы переноса, команды и фактические результаты сохранены в [tasks.md](tasks.md). Ниже описаны действующие архитектурные решения после удаления аудиомодуля; прежние операции интеграции не нужно повторять.

Модульная реорганизация уже отделила domain от UI/storage. Отменённый Dictation использовал те же словари, поэтому сохраняются vocabulary/language и общая SQLite. Дизайн уточняет границы пяти оставшихся модулей.

## Goals / Non-Goals

**Goals:** один владелец сессии, независимые предметные модели, подготовленные storage-входы и рекурсивные правила для будущих исходников.

**Non-Goals:** workspace, публичная библиотека, универсальные порты/интерфейсы, новая политика упражнений, перезапись словарей или миграция SQL.

## Decisions

### Модули и видимость

Корни app/ui/domain/storage/dataset оформлены каталогами. storage/mod.rs отвечает за инициализацию и внешний интерфейс; settings.rs — за JSON; catalog.rs — за таблицы, seed и материал упражнений. domain содержит settings, mode, typing, vocabulary и language. UI содержит меню, выбор режима, настройки, печать и результат. Межмодульные проверки — src/tests под cfg(test).

```text
main --> app
app --> ui, domain, storage
ui --> domain
storage --> domain, dataset
build.rs --> dataset
```

Main также объявляет корни; каждый модуль может использовать собственную реализацию. Корни экспортируют необходимое через pub(crate), дочерние детали остаются закрытыми/pub(super). Код приложения не зависит от main, build или src/tests. Направленные разрешения исключают межмодульные циклы без общего graph framework; отдельные crates не нужны при одном потребителе.

### Владение сессией и представление

App остаётся конкретным координатором с Ratatui/Crossterm: создаёт storage, владеет экраном, активной TypingSession и параметрами restart. Domain владеет текстом, языковыми политиками, таймером/причиной завершения, WPM/точностью и запоздавшим дополнением последней графемы. Операции принимают символы и предметные действия, не KeyEvent.

UI переводит клавиши в операции и отображает заимствованное состояние. Enter вводит только ожидаемый перевод строки. При результате допустимое продолжение последней графемы передаётся сессии; другая клавиша окончательно закрывает ввод перед навигацией. Время первоначального завершения фиксировано. Черновик Settings и фокус остаются у UI, запись выполняется только через app/storage; ResultView не дублирует статистику.

Settings/defaults/Serde и TestMode остаются в domain. Поддерживаемые поля сохраняют имена и значения; точечное удаление старых полей и нормализация dictation→typing определены remove-dictation. Не возвращать модель/виджет Dictation, аудиостатусы или операции процессов.

### Storage адаптирует общий формат

dataset — общий парсер/валидатор для build.rs и приложения без зависимостей на domain/storage. Ссылки #[path] и build tracking указывают на src/dataset/mod.rs. Storage валидирует профиль, выдаёт совместимые наборы и перемешанный материал Typing/Translation; испанские слова и фразы сохраняют строгий регистр Translation. DictationMaterial и два диктантных метода удалены из целевого интерфейса.

App/UI не импортируют Profile, не разбирают descriptor JSON и не выбирают политику по id. Сохраняются fallback существующих локальных наборов по таблице/языку, порядок списков и понятные ошибки повреждённых данных. Поле VocabularyEntry.es и сериализация словарей не переименовываются.

### Тесты и ограничения

Межмодульные тесты vocabulary/typing/storage находятся в src/tests, чтобы не добавлять тестовые разрешения runtime-модулям. Локальные тесты остаются в модуле, если соблюдают его реальные границы. Сохраняются прямые правила ArchUnitRust 0.0.2, непустые рекурсивные селекторы и запрет подавления анализа.

Внешние зависимости следуют обязанностям: terminal crates для UI/app, Serde/Unicode для domain, storage crates для storage, Serde/нормализация для dataset. Точные списки находятся только в тестах. Синтаксический анализ не доказывает cfg-выбор компилятора, сгенерированный код, алиасы crates и смысл побочных эффектов; эти ограничения остаются предметом ревью.

Проверять единственную цель `architecture`, именованные правила внутренних/внешних зависимостей и размещения исходников. Негативные проверки выполняются в временной копии и должны достигать конкретного архитектурного правила, а не только ошибки компиляции: UI→storage, app→dataset, неправильная ссылка нового вложенного исходника и обнаруженный исходник вне разрешённых корней. Сохранить запрет маркера подавления анализа.

`cargo test --locked --test architecture` и `cargo test --locked --all-features --all-targets` выполняют набор; терминальные сценарии запускаются через `cargo test --locked --test e2e` на Unix с изолированным `WPM_DATA_DIR`. Windows-сборка не является PTY-приёмкой. Нет необходимости в аудиодвойнике или проверке слышимости удалённого режима.

## Risks / Trade-offs

- Выделение сессии меняет событие завершения → сохранять E2E графем, таймера, результата и restart.
- Изменение адаптеров сбрасывает данные → проверять старую БД, профиль и поддерживаемые настройки.
- Межмодульный тест расширяет runtime API → отдельная тестовая область и минимальная видимость.

## Migration Plan

Прежний перенос уже выполнен; текущая работа удаляет только диктантный срез по remove-dictation. Полные действующие delta-блоки согласованы с конечной структурой и не возвращают удалённые модули при дальнейшей синхронизации. Данные не требуют преобразования. История прежней приёмки и незавершённых чужих аудиопроверок сохраняется; автоматического архива нет.
