# Design

## Context

Актуализировано 16 ноября 2026 в рамках [remove-dictation](../remove-dictation/proposal.md). Выполненные этапы переноса, команды и фактические результаты сохранены в [tasks.md](tasks.md). Ниже описаны действующие архитектурные решения после удаления аудиомодуля; прежние операции интеграции не нужно повторять.

Исторический перенос объединил одиннадцать E2E-целей и разделил архитектурные правила. Текущий контракт сохраняет организацию, а не число сценариев удалённой функции.

## Goals / Non-Goals

**Goals:** обнаруживаемые Cargo-наборы, единые helpers, выбор полного имени сценария и обычная параллельная приёмка.

**Non-Goals:** новый тестовый framework, производственные test-only API, сериализация всех тестов, сохранение аудиодвойника после удаления режима.

## Decisions

### Стандартные точки входа

Cargo обнаруживает tests/e2e/main.rs, tests/architecture/main.rs и tests/dataset_format.rs без [[test]]. Старые корневые e2e_*.rs и architecture.rs отсутствуют. main.rs E2E подключает common ровно один раз, сценарии импортируют crate::common; весь набор ограничен cfg(unix).

Архитектурный main.rs подключает internal_dependencies, external_dependencies и source_layout. Удаление audio убирает только относящиеся к нему правила/разрешения; остальные именованные правила остаются отдельными, понятными и рекурсивными.

### Изоляция и параллельность

TestDataDir и окружение дочерней команды изолируют каждый сценарий. Не менять глобальное окружение тестового процесса, не вводить общую блокировку или --test-threads=1. При сбое проверять готовность терминала и изоляцию ресурсов, не скрывать проблему ослаблением утверждений. FakeAudio удаляется вместе с диктантом; отрицательная проверка неиспользования старой переменной определяется remove-dictation.

### Выбор сценариев

Полный набор: cargo test --locked --test e2e. Полные имена: cargo test --locked --test e2e -- --list. Группы выбираются фильтром подстроки; settings:: совпадает и с spanish_settings::. Один сценарий выбирается полным именем и -- --exact. Windows не содержит Unix PTY-сценариев и не подтверждает их поведение.

### Документы и согласованная карта

ARCHITECTURE.md остаётся указателем на основную спецификацию и tests/architecture/. Действующие инструкции используют новые пути и команды; исторические команды в tasks не переписываются. Карту и архитектурные разрешения сохранять в согласованном виде app/ui/domain/storage/dataset, без audio.

### Приёмка

Сверять Cargo discovery и полные имена тестов, гарантируя отсутствие дубликатов. Все сценарии поддерживаемых режимов сохраняются; смешанные сценарии каталогов и Translation нельзя удалять вместе с диктантом. Новые проверки миграции и отсутствия аудио добавляются по remove-dictation. Исторические абсолютные числа тестов не являются ограничением.

Проверять единственную цель `architecture`, именованные правила внутренних/внешних зависимостей и размещения исходников. Негативные проверки выполняются в временной копии и должны достигать конкретного архитектурного правила, а не только ошибки компиляции: UI→storage, app→dataset, неправильная ссылка нового вложенного исходника и обнаруженный исходник вне разрешённых корней. Сохранить запрет маркера подавления анализа.

`cargo test --locked --test architecture` и `cargo test --locked --all-features --all-targets` выполняют набор; терминальные сценарии запускаются через `cargo test --locked --test e2e` на Unix с изолированным `WPM_DATA_DIR`. Windows-сборка не является PTY-приёмкой. Нет необходимости в аудиодвойнике или проверке слышимости удалённого режима.

## Risks / Trade-offs

- Перенос или удаление функции теряет полезную проверку → сверять сценарии поддерживаемого поведения и их полные имена.
- Общий процесс создаёт гонки окружения → задавать окружение только дочерним командам и сохранять TestDataDir.
- Старый delta возвращает требования аудиоприёмки → текущие полные блоки согласованы с remove-dictation до будущего sync.

## Migration Plan

Прежний перенос повторять не нужно. При будущей синхронизации применяются MODIFIED уже опубликованных требований; они не восстанавливают audio/FakeAudio и не фиксируют историческое число тестов. Текущая приёмка проходит по remove-dictation без SDK workaround и системных правок. Архивирование не выполняется автоматически.
