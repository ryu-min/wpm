# Design

## Context

Актуализировано 16 ноября 2026 в рамках [remove-dictation](../remove-dictation/proposal.md). История реализации и прежней приёмки сохранена в [tasks.md](tasks.md); отменённые аудиопроверки не объявлены выполненными. Эти действующие артефакты не требуют восстановления удаляемого режима.

Первоначальное добавление испанского уже реализовано; текущее согласование сохраняет его текстовую часть. SQLite содержит прежние RU/EN таблицы и добавочные `vocabulary_sets`/`vocabulary_entries`. Ресурсы позже переведены на общий формат `resources/datasets/`, а исходники — на модули domain/storage/app/ui. Этот дизайн описывает оставшиеся решения, не повторяет старый перенос файлов и не создаёт второго формата поставки.

## Goals / Non-Goals

**Goals:** общий языковой ввод, канонический каталог ES A1–C2, печать полных переводных пар, совместимость данных и настроек.

**Non-Goals:** аудио, микрофон, оценка речи, грамматика, интервальное повторение, сертификация CEFR, переименование полей существующей SQLite.

## Decisions

### Каталог и сохранность корпуса

`VocabularySet` содержит id, исходный/целевой язык и уровень, `VocabularyEntry` — стабильный id, русский перевод и каноническое слово. Язык задаётся участком, а не чередованием отдельных слов: русский перевод может содержать пробелы. Старый RU/EN JSON адаптируется к этой модели без переписывания хранения.

Шесть уровней содержат по 900–1100 обычных однословных строчных лемм, без собственных имён/аббревиатур; каждая лемма относится к одному уровню. Общий допуск — 5400–6600 слов. Нормализация NFC не объединяет `ano/año` и `si/sí`. Непустые переводы, id, объём и уникальность проверяются автоматически; коллизии упрощённого ввода не удаляются.

Происхождение, темы уровней и результаты содержательной редакторской проверки описываются в `resources/ru_es_catalog.md`. Оригинальную подборку нельзя подменять механическим переводом английского корпуса или выдавать внешний импорт за авторский материал. При внешних данных сохраняются источники и условия использования. Числовой валидатор не доказывает правильность перевода; сохраняется содержательная проверка сомнительных записей и выборки не менее 30 записей каждого уровня.

Испанские таблицы добавлены без разрушительной миграции RU/EN JSON. Встроенные наборы транзакционно добавляются только при отсутствии id; локальные изменения не перезаписываются, повреждённый набор не превращается в пустую успешную сессию. Поставка идёт через общий descriptor/parser/build механизм data-driven-exercise-datasets.

### Языковой ввод и статистика

Общий модуль language не зависит от SQLite или виджетов. Сначала принимается точное совпадение, затем соответствие физических RU/ENG-клавиш и разрешённая ES-эквивалентность; правила ES не распространяются на русский/английский участок и сохраняют регистр. Backspace удаляет целую графему. Канонический образец не меняется. Дополнительные кодовые точки составного знака не увеличивают WPM.

Последняя графема может поступить несколькими событиями терминала. Поэтому достижение длины в `Typing`/`Translation` по-прежнему сразу показывает Result, но оставляет возможность дописать только составные знаки этой последней графемы. Пока не пришло иное нажатие клавиши, последовательные combining marks принимаются, если дополняют последнюю существующую графему и не увеличивают число графем; их допустимость для цели проверяется общими правилами, а не фильтром при приёме. Неверный знак тоже должен попасть в проверку. Accuracy и числитель WPM пересчитываются, время фиксируется при первоначальном переходе в Result. Время ожидания составного знака не увеличивает длительность и не понижает WPM само по себе. Искусственной задержки перед Result и временного окна для знаков нет.

Первое нажатие, которое не является таким продолжением, окончательно закрывает ввод завершённой попытки и затем обрабатывается обычным экраном Result. Enter, Escape, стрелки и Ctrl+C сохраняют прежнее действие; Backspace не возвращает к упражнению и не удаляет завершённую графему. После restart/выхода поздний знак не меняет предыдущую попытку. Завершение по лимиту времени сразу окончательно и не принимает знаки после лимита. Причину завершения и фиксированное время следует хранить явно; нельзя заново вычислять завершение по таймеру на уже открытом результате. Это узкое правило завершения ввода, а не режим редактирования результата.

Translation проверяет видимый образец после каждого нажатия. Enter вставляет только ожидаемый разделитель пары, Backspace может вернуться через него. Завершение, результаты и restart используют существующую сессию печати. Все пути запуска используют одну языковую политику независимо от настройки конвертации обычного Typing.

### Приёмка и дальнейшая синхронизация

Сохраняются E2E каталога, старой БД, RU/EN, испанских пар, выбора/сохранения, Enter/Backspace и раздельной доставки последнего combining mark. Полный прогон — `cargo test --locked --all-features --all-targets`; Unix PTY не доказывает Windows-интерфейс. Содержательная проверка корпуса остаётся отдельным свидетельством.

Активные deltas содержат только spanish-vocabulary, spanish-translation и keyboard-layout-conversion. Будущий sync не должен создавать удалённые spanish-audio/spanish-dictation. Отмена старых задач 6.3/6.4 не является выполненной аудиоприёмкой; старый 6.5 остаётся исторически незавершённым. Текущая совместимость legacy settings и отсутствие запуска аудио проверяются в remove-dictation.

## Risks / Trade-offs

- Упрощённый ввод не проверяет знание диакритики → сообщать ограничение и сохранять каноническое написание.
- Валидатор не оценивает качество перевода → сохранять редакторскую проверку и её фактический статус.
- Поздняя составная графема может изменить результат → сохранять явную причину/момент завершения и E2E доставки по событиям.
- Повторный seed может стереть локальные изменения → добавлять только отсутствующие id и проверять два запуска старой БД.

## Migration Plan

Общие таблицы, данные и поддерживаемые настройки сохраняются. Удаление старых диктантных полей и нормализация Quick Start принадлежат remove-dictation; здесь не требуется SQL-откат. При будущей синхронизации используются только текущие три delta specs. Архивирование не выполняется автоматически.
