# Design

## Context

Мотивация и состав описаны в `proposal.md` и `specs/spanish-cafe-beginner-set/spec.md`. Реализация испанских режимов уже находится в рабочем дереве: `VocabularyEntry` хранит `id/ru/es`, `VocabularySet` используется обоими режимами, ресурсы встраиваются через `include_str!`, а `seed_spanish` транзакционно добавляет отсутствующие наборы. Settings и Select Mode получают имена из БД, диктант фильтрует их по `ru_es_`. Новому набору не нужен отдельный экран.

Многословные строки уже проходят через перевод, ввод и аудио. Ограничение находится в содержимом исходного корпуса, его валидаторе и контракте регистра: `Dictation::submit` использует строгое по регистру испанское сравнение, виджет всегда пишет `Type lowercase; accents are optional`. Имя и начало предложения невозможно надёжно отличить на слух только по регистру.

Активное `add-spanish-translation-and-dictation` реализовано, но задачи 6.3–6.5 ещё не закрыты: ручная аудиоприёмка, Windows и итоговое согласование. Его тексты запрещают фразы/имена для исходного корпуса. Новая capability вводит явное узкое исключение для `ru_es_cafe_beginner`; остальные ограничения остаются у A1–C2. Текущие опубликованные спецификации не описывают испанский каталог, поэтому здесь добавляется отдельная capability, а не MODIFIED отсутствующего основного spec.

## Goals / Non-Goals

**Goals:** добавить маленький набор через существующий каталог, сохранить пользовательские данные и каноническое написание, поддержать честную проверку фразы на слух с минимальным изменением модели сессии.

**Non-Goals:** импорт Duolingo, редактор наборов, обучение грамматике/произношению, автоматические варианты ответа с пропуском `yo`, изменение объёма или состава A1–C2, новый выбор голоса, миграция схемы БД и глобальное отключение проверки регистра.

## Decisions

### 1. Один ресурс и явные метаданные набора

Добавить `resources/ru_es_cafe_beginner.json` в прежнем формате массива `id/ru/es`; идентификатор каждой записи — `ru_es_cafe_beginner:` плюс точное каноническое ES-поле в NFC. Пробелы и регистр допустимы внутри id. Это продолжает существующее правило идентификаторов и делает пересечения с A1 безопасными. Нормализацию имени `Serjio` в `Sergio` и `Espana` в `España` выполнить при подготовке данных, а не при загрузке пользовательских записей.

В перечне ресурсов `seed_spanish` явно хранить level: прежние `a1`–`c2`, для нового `beginner`. Выводить level через `name[6..]` для нового id неверно. Схема таблиц сохраняется. Новые таблицы/универсальный реестр пользовательских курсов не нужны. Существующее добавление только отсутствующих наборов и единая транзакция сохраняются; не ремонтировать и не перезаписывать существующий набор с таким id молча.

Обновить `resources/ru_es_catalog.md` и README: описать тематический набор отдельно от 5675 лемм A1–C2, перечислить нормализацию пользовательских заметок, исключить заявление о точном составе Duolingo. Полный список кафе — самостоятельная подборка общих слов и коротких выражений, а не копия чужого курса.

### 2. Узкая политика сессии диктанта

При создании сессии в `App::start` определить специальную политику по точному id `ru_es_cafe_beginner`. Передать в `Dictation` небольшой флаг/enum для сравнения без учёта регистра и соответствующей подсказки. По умолчанию оставить прежнее строгое сравнение: старые наборы, существующие тестовые фикстуры и перезапуск должны сохранить поведение.

Для нового набора перед существующим испанским сравнением привести копии ввода и ожидаемой строки к одному регистру. Не изменять `VocabularyEntry`, строку аудио, видимый ответ или введённый пользователем текст. Нормализация должна продолжать принимать RU-клавиши и испанскую диакритику, не превращаясь в фонетическую транслитерацию. `Translation` по-прежнему использует исходную Spanish policy и канонический регистр. Общую функцию сравнения менять только если небольшой явный параметр позволяет избежать дублирования; не добавлять настройки/колонки БД для будущих гипотетических наборов.

Передавать подсказку через безопасное `InputView`, не раскрывая в нём текущую запись. Использовать одинаковую подсказку для всего тематического набора, например `Type a word or phrase; case and accents are optional`. Предварительная подсказка не сообщает длину, перевод или число слов конкретного ответа. Существующие надписи счётчиков можно сохранить; в документации объяснить, что одна фраза считается одной записью.

Альтернативы: хранить имена и страны строчными — портит учебный материал; требовать угадать регистр на слух — добавляет искусственные ошибки; менять регистр для всех режимов/наборов — ненужное расширение. Выбранное исключение сохраняет корректную орфографию и прежнее поведение.

### 3. Приёмка через терминал и проверки каталога

Добавить `tests/e2e_spanish_cafe.rs`, используя существующие `TestDataDir`, `WPM_DATA_DIR`, PTY и `FakeAudio`; при необходимости небольшое расширение helpers только для управления тестом. Реальное добавление набора проверить на свежей и заранее заполненной БД без `seed_spanish` для нового id. Дважды запустить бинарник, затем проверить через экран настройки сохранение старого выбора/доступность нового и через SQLite точный состав/отсутствие дублей.

Проверить выбор и сохранение для прямого запуска, Quick Start и Select Mode обоих режимов. Полное прохождение встроенного набора случайно перемешивается: для сценария 31 записи либо управлять PTY по событиям `FakeAudio` (ожидание с ограничением времени), либо после каждого озвученного задания отправлять заведомо неверный ответ и проверять раскрытую запись, собрав все 31 значения из screen/transcript. Второй вариант не требует угадывать порядок и подтверждает счётчик и отсутствие повторов; запустить длину 50. Не читать скрытый ответ из UI до Enter.

Пограничные проверки фраз выполнить детерминированно на маленьких фикстурах с тем же id: правильный/строчный ввод, `Espana`, RU-клавиши, пробелы, ошибка неполной фразы, повтор F2, скрытый ответ, раскрытие и выход Escape. Полный каталог отдельно сверить с таблицей spec, чтобы фикстуры не заменяли проверку поставки. Для Translation использовать двухфразовую фикстуру, допускающую любой порядок, и довести ввод до результата с 100% accuracy; отдельно проверить отсутствие зависимости от аудио.

Существующий `scripts/validate_spanish_catalog.py` намеренно валидирует шесть уровней и остаётся строгим. Новый небольшой набор проверяется отдельным Rust-тестом ресурса: точные 31 пары, стабильные уникальные id, NFC, допустимые испанские буквы/одинарные внутренние пробелы, отсутствие внешних пробелов/кириллицы в ES. Пересечения лемм с A1–C2 допустимы. Обновить ожидание общего числа наборов в тесте миграции, не ослабляя шестирежимный структурный контракт.

Терминальный дублёр доказывает передачу полной канонической фразы в TTS, но не разборчивость звука. При apply отдельно прослушать `café con leche`, `Me llamo Sergio`, `Vivo en España` с доступным реальным eSpeak NG, записав платформу и результат; при отсутствии звукового окружения оставить этот пункт незавершённым с причиной. Непроверенные ОС прежнего изменения не считаются автоматически проверенными.

## Risks / Trade-offs

- [Точный список первого модуля Duolingo не известен] → фиксированный оригинальный тематический список без обещания точного совпадения.
- [Исключение регистра может распространиться на старые наборы] → определять политику по точному id, проверять A1 и Translation регрессионными сценариями.
- [Новая запись с фразой ломает общее ожидание только лемм] → отдельный контракт и тест набора; валидатор шести уровней не расширять до фраз.
- [Активные испанские спецификации ещё не синхронизированы] → применять поверх имеющейся реализации; при будущей синхронизации учитывать явное исключение этой capability. Не объявлять прежнее изменение завершённым и не архивировать его в рамках данной задачи.

## Migration Plan

Обновлённый бинарник добавляет отсутствующий набор обычной транзакцией при запуске. Сохранённые настройки и записи не перезаписываются; дефолты остаются прежними. Откат приложения не требует удаления данных: прежняя версия уже умеет читать этот формат и имена с `ru_es_`, но проверяет регистр строго, поэтому перед откатом можно выбрать прежний A1–C2. Удалять наборы пользователя при откате не требуется.
